## Project Architecture

SmartCampus is a full-stack event management platform for campus organizations built with:
- **Frontend**: Next.js 15 (App Router) + React 19
- **Backend/CMS**: Payload CMS 3.x (headless CMS)
- **Database**: MongoDB
- **Language**: TypeScript

## Getting Started

### Prerequisites
- Node.js 18+ (recommended: 18 LTS)
- pnpm (or npm/yarn)
- MongoDB (local or remote instance)

### Option 1: Local Setup (without Docker)

1. **Clone the repository**
   ```bash
   git clone <repository-url>
   cd SmartCampus
   ```

2. **Install dependencies**
   ```bash
   pnpm install
   ```

3. **Configure environment variables**
   ```bash
   cp .env.example .env
   ```
   Edit `.env` and set required values (see [Environment Variables](#environment-variables))

4. **Start MongoDB**
   - Install MongoDB locally, OR
   - Use a cloud MongoDB instance (Atlas)

5. **Run development server**
   ```bash
   pnpm dev
   ```

6. **Access the application**
   - Frontend: http://localhost:3000
   - Payload Admin: http://localhost:3000/admin
   - GraphQL Playground: http://localhost:3000/api/graphql-playground

7. **Create first admin user**
   - Navigate to http://localhost:3000/admin
   - Follow on-screen instructions to create your first admin account

### Option 2: Docker Setup

1. **Clone and configure**
   ```bash
   git clone <repository-url>
   cd SmartCampus
   cp .env.example .env
   ```

2. **Update DATABASE_URI in .env**
   ```env
   DATABASE_URI=mongodb://mongo/smartcampus
   ```

3. **Start Docker containers**
   ```bash
   docker-compose up
   ```
   Add `-d` flag to run in background

4. **Access the application**
   - Same as above (http://localhost:3000)

### Running Tests

```bash
# Run all tests
pnpm test

# Run integration tests only
pnpm test:int

# Run E2E tests only
pnpm test:e2e
```

## Environment Variables

Required environment variables for local development:

### Database
- `DATABASE_URI` - MongoDB connection string
  - Local: `mongodb://127.0.0.1/smartcampus`
  - Docker: `mongodb://mongo/smartcampus`
  - Cloud: `mongodb+srv://user:pass@cluster.mongodb.net/dbname`

### Authentication
- `PAYLOAD_SECRET` - Secret key for JWT signing (min 32 characters)
  - Generate: `openssl rand -base64 32`

### Optional
- `NODE_OPTIONS` - Node.js runtime options
  - Default: `--no-deprecation`
- `PORT` - Server port (default: 3000)

### Example .env file
```env
DATABASE_URI=mongodb://127.0.0.1/smartcampus
PAYLOAD_SECRET=your-very-secure-random-secret-key-here
```

**⚠️ Security Note**: Never commit `.env` files with real credentials to version control!

## Data Flow

### 1. User Authentication Flow

```
User → Login Form → POST /api/auth/login
                    ↓
                    Payload Auth API
                    ↓
                    JWT Token Generated
                    ↓
                    Stored in localStorage
                    ↓
                    AuthContext provides user state
                    ↓
                    All API requests include: Authorization: Bearer <token>
```

### 2. Event Join Flow

```
User clicks "Join Event" button
    ↓
JoinEventButton.tsx → handleJoin()
    ↓
POST /api/events/:id/join (with JWT in header)
    ↓
Backend verifies JWT → extracts user ID
    ↓
Check if event exists & is active
    ↓
Check EventParticipations for existing record
    ↓
If not exists:
    Create EventParticipation { event, user, status: 'going' }
If exists:
    Update status to 'going'
    ↓
Count participants with status='going'
    ↓
Return { message, participation, participantsCount }
    ↓
Frontend updates UI:
    - Button text changes to "✓ Joined - Leave Event"
    - Display updated participants count
    - Show success toast
```

### 3. Events List Flow

```
User navigates to /events
    ↓
Page component fetches: GET /api/events (via Payload API)
    ↓
For each event:
    - Query EventParticipations count where status='going'
    - Attach participantsCount to event object
    ↓
Render EventCard components
    ↓
Each EventCard displays:
    - Event details (title, date, location)
    - Participants count: "👥 X uczestników"
```

## Main Modules

### 1. Events Module
**Location**: `src/collections/Events.ts`, `src/app/api/events/`

**Purpose**: Manage campus events (create, read, update, soft-delete)

**Key Features**:
- Event creation by logged-in users
- Soft delete (deletedAt field instead of hard delete)
- Status tracking: draft, active, cancelled
- Organization relationship (N:1)
- Slug generation for SEO-friendly URLs
- Date validation (prevent past events)

**Access Control**:
- Read: Public (non-deleted only)
- Create: Logged-in users
- Update: Event creator, org-admin, super-admin
- Delete: Super-admin only

### 2. Organizations Module
**Location**: `src/collections/Organizations.ts`

**Purpose**: Student organizations that host events

**Key Features**:
- Organization types: club, association, department, other
- Status: active, pending, inactive
- Member management (via Users.organization relationship)
- Soft delete support
- Slug generation

**Access Control**:
- Read: Public (active only)
- Create: Staff, super-admin
- Update: Org-admin (own org), super-admin
- Delete: Super-admin only

### 3. EventParticipations Module
**Location**: `src/collections/EventParticipations.ts`

**Purpose**: Many-to-many relationship between Users and Events

**Key Features**:
- Participation status: going, interested, cancelled
- Unique constraint on (event, user) pair via beforeChange hook
- Auto-set user from JWT context
- Timestamps for tracking

**Access Control**:
- Read: Public (for displaying counts)
- Create: Logged-in users
- Update: User can update their own participations
- Delete: User can delete their own participations

### 4. Users Module
**Location**: `src/collections/Users.ts`

**Purpose**: User authentication and profiles

**Key Features**:
- Auth-enabled (built-in JWT)
- Roles: student, org-admin, staff, super-admin
- Profile fields: firstName, lastName, studentId, organization
- Email verification ready
- Organization membership

**Access Control**:
- Read: Public (for displaying organizers)
- Create: Public (self-registration)
- Update: User can update own profile
- Delete: Super-admin only

### 5. Media Module
**Location**: `src/collections/Media.ts`

**Purpose**: File uploads (images, documents)

**Key Features**:
- Image resizing (via Sharp)
- Focal point selection
- Predefined sizes for optimization
- Used by Events and Organizations

## API Documentation

### Authentication Endpoints

#### POST /api/auth/login
- **Body**: `{ email, password }`
- **Response**: `{ token, user }`

#### POST /api/auth/register
- **Body**: `{ email, password, firstName, lastName }`
- **Response**: `{ token, user }`

#### GET /api/auth/me
- **Headers**: `Authorization: Bearer <token>`
- **Response**: `{ user }`

#### POST /api/auth/logout
- **Headers**: `Authorization: Bearer <token>`
- **Response**: `{ message }`

### Event Participation Endpoints

#### POST /api/events/:id/join
- **Headers**: `Authorization: Bearer <token>`
- **Response**: 
  ```json
  {
    "message": "Successfully joined event",
    "participation": { ... },
    "participantsCount": 42
  }
  ```

#### POST /api/events/:id/leave
- **Headers**: `Authorization: Bearer <token>`
- **Response**: 
  ```json
  {
    "message": "Successfully left event",
    "participation": { ... },
    "participantsCount": 41
  }
  ```

#### GET /api/events/:id/participants
- **Response**: List of participants with user details

### Payload CMS REST API

All Payload collections are automatically exposed via REST API:

- `GET /api/events` - List all events
- `GET /api/events/:id` - Get event by ID
- `POST /api/events` - Create event (requires auth)
- `PATCH /api/events/:id` - Update event (requires auth)
- `DELETE /api/events/:id` - Delete event (requires auth)

Same pattern for: `/api/users`, `/api/organizations`, `/api/event-participations`, `/api/media`

**Query Parameters**:
- `?where[field][operator]=value` - Filtering
- `?limit=10` - Pagination
- `?sort=-createdAt` - Sorting
- `?depth=2` - Population depth for relationships

### Payload Admin Panel

- **URL**: http://localhost:3000/admin
- **Features**:
  - Visual content editor
  - Collection management
  - User management
  - Media library
  - GraphQL playground

## Frontend-Backend Communication

### How FE Communicates with BE

1. **API Client** (`src/lib/api.ts`):
   - Centralized fetch wrapper
   - Automatically attaches JWT from localStorage
   - Handles errors uniformly

2. **AuthContext** (`src/contexts/AuthContext.tsx`):
   - Manages authentication state
   - Provides user object to all components
   - Handles login/logout

3. **Server Components** (Next.js 15):
   - Can directly query Payload on the server
   - No API calls needed for initial page loads

4. **Client Components**:
   - Use `api.ts` helper for authenticated requests
   - Store JWT in localStorage
   - Include `Authorization: Bearer <token>` header

### Example API Call
```typescript
// In a React component
import { api } from '@/lib/api'

const handleJoinEvent = async (eventId: string) => {
  const { data, error } = await api.events.join(eventId)
  
  if (error) {
    alert(error)
    return
  }
  
  console.log('Joined!', data.participantsCount)
}
```

## Payload Collections Defined

All Payload collections are defined in `src/collections/`:

- **Location**: `src/collections/*.ts`
- **Registered**: `src/payload.config.ts` → `collections` array
- **Types**: Auto-generated in `src/payload-types.ts` (via `pnpm generate:types`)

Each collection file exports a `CollectionConfig` object with:
- `slug` - API endpoint name
- `fields` - Schema definition
- `access` - Permission rules
- `hooks` - Lifecycle events (beforeChange, afterChange, etc.)
- `admin` - Admin panel configuration

## Development Tips

### Generate TypeScript Types
When you modify collections, regenerate types:
```bash
pnpm generate:types
```

### Reset Database
```bash
# Drop MongoDB database
mongo smartcampus --eval "db.dropDatabase()"

# Or via MongoDB Compass / Atlas
```

### Debug Mode
Add to `.env`:
```env
NODE_OPTIONS="--no-deprecation --inspect"
```

### Rate Limiting
Custom endpoints use rate limiting (see `src/lib/rateLimiter.ts`):
- Default: 10 requests per minute per IP

### Soft Delete Pattern
Events and Organizations use soft delete:
- Set `deletedAt: Date` instead of removing document
- Filter `deletedAt: { exists: false }` in queries

## Troubleshooting

### "Cannot connect to MongoDB"
- Check DATABASE_URI in .env
- Ensure MongoDB is running
- For Docker: use `mongodb://mongo/smartcampus`
- For local: use `mongodb://127.0.0.1/smartcampus`

### "Invalid token"
- Token may have expired
- Log out and log back in
- Check PAYLOAD_SECRET is set correctly

### Port 3000 already in use
```bash
# Find process using port 3000
lsof -ti:3000 | xargs kill -9

# Or change port
PORT=3001 pnpm dev
```

### Docker issues
```bash
# Rebuild containers
docker-compose down
docker-compose up --build

# Clear volumes
docker-compose down -v
```
